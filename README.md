# Сервис сокращения ссылок на Java

[![Java CI](https://github.com/Timur3005/url-shortener-java/actions/workflows/ci.yml/badge.svg)](https://github.com/Timur3005/url-shortener-java/actions/workflows/ci.yml)

Консольное приложение: сокращает HTTP(S) URL, ограничивает число переходов,
автоматически удаляет ссылки по TTL и сохраняет данные между запусками.
Пользователь определяется UUID без регистрации. Настройки находятся в отдельном файле.

## Установка и запуск

Нужен **JDK 17 или новее**, включая модуль `java.desktop` для открытия браузера.
Отдельно устанавливать Maven и библиотеки не требуется: Maven Wrapper скачает
закреплённый Maven 3.9.9, зависимости тестирования и форматирования — из Maven Central.
Первой сборке нужен интернет. На macOS/Linux нужны `curl` или `wget`, `unzip`
и `sha256sum` или `shasum` для проверки контрольной суммы;
на Windows — PowerShell.

```bash
git clone https://github.com/Timur3005/url-shortener-java.git
cd url-shortener-java
./mvnw clean verify
java -jar target/url-shortener.jar
```

На Windows вместо `./mvnw` используйте `.\mvnw.cmd`.
Команды запуска выполняйте из корня проекта. Можно передать другой файл настроек:

```bash
java -jar target/url-shortener.jar config/application.properties
```

## Команды

`<link>` — код или полная короткая ссылка, возвращённая `create`.
Угловые скобки вводить не нужно. URL с пробелами нужно предварительно закодировать (`%20`).

| Команда | Результат |
| --- | --- |
| `help` | Справка и примеры |
| `create <url> [limit]` | Создать ссылку; без `limit` используется значение конфигурации |
| `open <link>` | Открыть исходный URL в браузере и учесть переход |
| Полная короткая ссылка отдельной строкой | То же, что `open` |
| `list` | Показать свои ссылки, счётчики и срок действия |
| `update <link> limit <number>` | Изменить лимит своей ссылки |
| `update <link> url <url>` | Изменить адрес своей ссылки |
| `delete <link>` | Удалить свою ссылку |
| `notifications` | Посмотреть свои уведомления |
| `user` | Показать текущий UUID |
| `user new` | Перейти в новую анонимную сессию |
| `user use <uuid>` | Переключиться на существующий UUID |
| `exit` | Сохранённые данные остаются на диске, приложение завершается |

Пример сеанса:

```text
create https://www.baeldung.com/java-9-http-client 2
user
list
```

Сохраните показанный UUID. Вместо `CODE` ниже подставьте выданный код:

```text
open CODE
open CODE
open CODE
notifications
update CODE limit 5
update CODE url https://ru.stackoverflow.com
delete CODE
exit
```

Первые два перехода разрешены, третий блокируется. После увеличения лимита до 5
доступны ещё три перехода: счётчик не сбрасывается. Если уменьшить лимит до числа
уже совершённых переходов или ниже, ссылка сразу блокируется.
Изменение URL или лимита не продлевает TTL.

Для проверки нескольких пользователей сохраните UUID первого, выполните `user new`
и создайте ссылку на тот же URL. Код будет другим. Второй пользователь не сможет
изменить или удалить ссылку первого. Вернуться можно командой `user use <uuid>`.

## Настройки

Файл [config/application.properties](config/application.properties) обязателен.
Изменения применяются после перезапуска.

| Ключ | По умолчанию | Назначение |
| --- | --- | --- |
| `short.base-url` | `https://short.local/` | Префикс коротких ссылок |
| `link.ttl` | `PT24H` | Время жизни новых ссылок в формате `Duration` |
| `link.default-limit` | `10` | Лимит при создании без явного значения |
| `link.max-limit` | `1000000` | Максимально допустимый лимит |
| `cleanup.interval` | `PT1S` | Период фоновой очистки |
| `storage.path` | `data/state.properties` | Файл состояния |

TTL должен быть положительным и не превышать 3650 дней, период очистки —
от `PT0.001S` до `P365D`; лимиты — целыми положительными числами,
default-limit не больше max-limit, max-limit не больше 1 000 000 000.
Для проверки TTL можно установить `PT1H`
(час) или `PT5S` (пять секунд). Это системная настройка: команды изменения TTL нет.
Существующие ссылки сохраняют первоначальный `expiresAt` после изменения настроек.
Относительный `storage.path` отсчитывается от **рабочего каталога процесса**.

## Срок действия и уведомления

Последний разрешённый переход открывает URL и создаёт уведомление владельцу об
исчерпании лимита. Повторные заблокированные переходы не создают дубликаты.
Повысив лимит, владелец может восстановить доступ, пока не закончился TTL.

В момент `expiresAt` ссылка уже недоступна. Фоновая очистка удаляет истёкшие записи
с периодом `cleanup.interval`; дополнительно срок проверяется при операциях.
Владельцу сохраняется уведомление об истечении TTL. Проверка при запуске учитывает
время, пока приложение было выключено. При выключенном приложении очистка не работает.
Команда `notifications` показывает сохранённый журнал текущего пользователя:
прочтение не удаляет записи. Повторное достижение нового лимита после его повышения
создаёт новое уведомление.

## Архитектура

Один Maven-модуль, три слоя:

| Модуль/пакет | Ответственность |
| --- | --- |
| `core` | Модель ссылки, конфигурация, лимиты, TTL, UUID, проверки владельца, уведомления; интерфейсы инфраструктуры |
| `infra` | Файловое хранилище, браузер и фоновая очистка |
| `cli` | Разбор команд и сообщения пользователю |
| `Main` | Сборка зависимостей, запуск и завершение |
| `src/test` | Unit-тесты и интеграционные сценарии с временным хранилищем и подменой браузера |

Каждое создание даёт новый код; проверка коллизий препятствует перезаписи ссылки.
Время передаётся через `Clock`, браузер — через интерфейс, поэтому тесты не зависят
от реального времени и не открывают вкладки. Фоновая очистка и консоль используют
один сервис с синхронизацией изменений.

Состояние сохраняется при изменениях, а не только при `exit`. Временный файл
записывается рядом с основным и заменяет его атомарно. Файловая блокировка
препятствует одновременному запуску двух копий с одним хранилищем.
Каталог `data/` исключён из Git: он содержит UUID, URL и уведомления.

## Тестирование

```bash
./mvnw test              # unit и интеграционные тесты
./mvnw clean verify      # сборка JAR, все тесты, проверка стиля
./mvnw spotless:apply    # применить Google Java Format после правок
```

В проекте 55 автоматических тестов (с учётом параметризованных сценариев).
Отчёты тестов: `target/surefire-reports/`. Тесты проверяют уникальность, точную границу
лимита и TTL, чужие UUID, редактирование, уведомления, сохранение и восстановление,
валидацию конфигурации/URL, обработку ошибок CLI и открытия браузера.
TTL проверяется управляемыми часами без ожидания часа или суток.

GitHub Actions запускает `clean verify` на Linux/Java 17, Windows/Java 17
и Linux/Java 21, затем запускает готовый JAR со справкой. Каждый запуск сохраняет
JAR и отчёты тестов как артефакты. Проверка форматирования Spotless входит в `verify`;
правила редактора заданы в `.editorconfig`. Workflow: [.github/workflows/ci.yml](.github/workflows/ci.yml).
